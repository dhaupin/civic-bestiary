# Repository notes

**The Civic Bestiary** - a field guide to the creatures of the body politic: satirical
portmanteaus for performative nationalism, bad-faith debate, hypocrisy, and algorithmic
radicalization. One dataset, two artifacts: a GitHub-flavored README and a prerendered
static site.

The frame is a naturalist's guide, and the vocabulary follows it everywhere: sections are
**orders**, entries are **species**, the example is a **sighting in the wild**, and the
cross-references are **compare with**. Code follows too (`.species-*`, `.listing-*`), so a
grep for "term" or "entry" should turn up nothing but the README's own prose.

## Layout

| Path | Role |
| --- | --- |
| `data/lexicon.json` | **Source of truth, meta half.** Title, description, preface, orders (sections). |
| `data/species/*.json` | **Source of truth, record half.** One file per species; the file name is the slug. |
| `packs/public/bestiary-shapes/` | The site's own verifier pack (packstruct SPEC v1): asserts the identification block, the field-guide links, and the read-more rows survive to baked HTML. |
| `poststruct.config.mjs` | Arms the artifact audit: points it at `web/dist`, arms the pack, names `data/` as the prose of record. |
| `README.md` | Generated by `build.py`. Never hand-edit. |
| `site.config.js` | **Identity**: name, wordmark, URL, nav, base routes, 404 copy. Adopted from `dhaupin/coreforge`. |
| `web/` | The site: coreforge's React/Vite shell, prerendered by `dhaupin/prestruct`. |
| `web/src/data/lexicon.js` | Generated by `build_site.py`; the app's only data import. |
| `web/ssr.config.js` | Adapter: reshapes `site.config.js` + species into prestruct config, including the `/species/<slug>` routes and the `DefinedTermSet` JSON-LD. |
| `build.py` / `build_site.py` | Generators, stdlib only. Both take `--check`. |

## Commands

```bash
python3 build.py            # regenerate README.md
python3 build_site.py       # regenerate web/src/data/lexicon.js
python3 build.py --check && python3 build_site.py --check   # CI gate: generated files current

npm run audit               # poststruct over web/dist: head/site/links/i18n/a11y/language + our pack
npm run lint:packs          # packstruct lint over packs/ --deep
npm run verify              # check + build + audit, end to end

npm --prefix web install    # once
npm --prefix web run build  # prestruct: validate -> vite build -> inject meta -> prerender -> audit
npm --prefix web run dev    # local dev server
```

`npm run build` at the root runs all three in order.

## Validation

`build.py` refuses to render when a term is duplicated, an entry is missing a required field,
a `related` reference is undefined or self-referential, a section id is unknown, or a term is
never listed in anyone else's `related` list (the cross-reference graph must stay connected).
After rendering it also verifies every internal `](#anchor)` target resolves.

`build.py` also refuses a record whose file name does not match its term's slug, a missing or
duplicated `order` inside an order, and an order with no species.

`prestruct build` fails on config errors and grades the baked HTML; a red audit is a real
defect (missing or duplicate title, bad canonical, absent OG tags, over-long description).

`poststruct` then audits the artifact prestruct just baked - the cheap half we do not write
ourselves: the internal link graph, i18n tags, a11y-lite (informative images, labels, skip
link), the site/feeds contract, and the language module (dash classes FAIL by default, so the
` - ` house rule is enforced rather than remembered). It also runs `packs/`. CI pins both
(`poststruct@1.2.0`, `packstruct@1.1.2`): an audit that floats is not a gate.

## Adding a species

1. Add `data/species/<slug>.json`. `slug` is the term lowercased with spaces as hyphens, so
   `Trust-Me-Brofessor` is `trust-me-brofessor.json` - the validator refuses a mismatch. Set
   `section` to the order id and `order` to one past that order's highest; `order` decides the
   rendered README number and the "No. 7 of 27" line, so appending means a new high number.
2. Add the new term to one existing entry's `related` list, swapping out its weakest link -
   lists are kept at three items, and the validator tells you if you skipped this.
3. `python3 build.py && python3 build_site.py`, then `npm --prefix web run build`.
4. Review the README diff and the new `/species/<slug>` page.

The site slug is derived from the term (`Trust-Me-Brofessor` becomes
`/species/trust-me-brofessor`), so it is stable. README anchors are GitHub's auto-generated
heading anchors (`#10-trust-me-brofessor`) and therefore **do** shift when an entry is
inserted mid-section. That is the one thing a renumber breaks; prefer appending.

## Site notes

- **Routes are `/` and `/species`.** The browse page was `/lexicon` and entries were
  `/term/<slug>` before the bestiary frame landed; nothing was deployed, so no redirects.
- **Adopted from coreforge, deliberately trimmed.** The shell's Jekyll `docs/` rig and its
  paint-scheme preset picker are not shipped: this site has one palette and no docs site.
  Everything else follows the family rules - tokens own the palette, theme is one
  `<html data-theme>` attribute, nav and footer render from `site.config.js`.
- **`siteUrl` is a placeholder** (`https://civicbestiary.example.com`). It is baked into
  canonicals, OG tags, and `sitemap.xml`, so replace it in `site.config.js` before publishing.
- The site expects a domain root. For a project page (`dhaupin.github.io/civicbestiary/`) set
  Vite's `base` in `web/vite.config.js` to the repo path.
- The repo URL is authored once, in `site.config.js` (`REPO`); the nav link, the footer, and
  the JSON-LD license all derive from it. A few surfaces still carry hand-copied identity and
  will drift on a rename: `web/public/site.webmanifest`, the `aria-label` in
  `web/public/icon.svg`, the canonical placeholder in `web/index.html`, the two
  `package.json` names, and the OG `alt` in `web/ssr.config.js`. Check them on any rename.
- `web/public/icon.svg` is the authored mark; `node scripts/icons.mjs` (run from `web/` after
  `npm i --no-save @resvg/resvg-js`) re-rasterizes the favicons and `og-image.png`.
- Deploy: `.github/workflows/pages.yml` builds and publishes `web/dist` to GitHub Pages.
- `.prestruct/cache/` makes rebuilds incremental; `npx prestruct clean` clears it.

## House style

- Two numbered senses per entry: one concrete ("who this person is"), one structural ("what
  the pattern does"). `notes` is optional and only for etymology or usage caveats.
- Every entry carries the three identification fields, and `build.py` fails without them:
  - `range` - one line of habitat: where you actually meet this thing.
  - `call` - the signature utterance in quotes, the line that identifies the species by ear.
  - `field_marks` - three short diagnostic traits, terse enough to scan. These are what you
    check before reading the description, so they stay concrete and observable.
  They render as an identification block on `/species/<slug>` and as a `Range / Call / Field
  marks` block in the README, between the etymology and the senses.
- `confused_with` is the pair edge: `[{ "term": "<existing term>", "tell": "<how to tell them
  apart>" }]`. The `tell` is the whole point - it must be a diagnostic ("the sophistroll knows
  the fallacy is a fallacy; the illogician believes it"), not a restatement of either entry.
  A twin is filtered out of `related` by both generators, so the same species never appears
  under both "Easily confused with" and "Compare with".
- `part_of_speech` and `ipa` use the loose conventions already in the file; IPA is
  approximate and follows the coining, not a dictionary.
- Prose uses ` - ` (spaced hyphen), never an em dash. The site converts quotes to curly at
  generation time; `lexicon.json` keeps straight quotes.
- The example is one line of reported speech, with the coined term in `**bold**` and the
  whole quote in italics. It is the "sighting in the wild"; `call` is the different thing -
  what the creature says, not what someone says about it.
- Voice is satirical and pointed, aimed at behavior, institutions, and power - never at
  identity, and never at the people on the receiving end. The bestiary frame carries the
  rule: the species is the pattern, not the person.
- Some species are trolls in the old sense (things under bridges demanding a toll), some in
  the internet sense. The preface says so; keep new entries consistent with whichever
  lineage they belong to.
